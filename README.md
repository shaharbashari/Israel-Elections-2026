# מבט — בחירות בישראל, עם המקורות

**כתובת האתר:** <https://shaharbashari.github.io/Israel-Elections-2026/>

מרחב מידע ציבורי עצמאי בעברית וב־RTL. זה אינו אתר ועדת הבחירות ואינו המלצת הצבעה. מצפן העמדות מחשב חפיפה עם עמדות מתועדות בלבד. פרסום גרסה ל־GitHub Pages הוא שלב נפרד; שינוי מקומי אינו מעיד שהאתר החי עודכן.

## מה אפשר לעשות

- להכיר את הרשימות שבמחקר בכרטיסים קומפקטיים, תמיד בסדר א״ב בעברית.
- לחפש במפורש לפי שם רשימה, שם חלופי או מרכיב שלה כפי שנמסר במחקר.
- לבנות מסלול קריאה בשלושה צעדים: תחומים שרוצים להבין, סוג התיעוד ועומק הקריאה. מסלול הקריאה אינו שואל על עמדות.
- לקרוא שאלה מול **כל הרשימות שבמאגר**, כולל אלה שחסר לגביהן תיעוד. בחירת תחומים, סוג מידע או עומק אינה מסננת או מדרגת רשימות.
- לפתוח את מצפן העמדות: כיוון אישי מול עמדות שקודדו מרשומות מחקר. האחוז ממוין מהגבוה לנמוך רק לרשימות עם לפחות שלוש שאלות מתועדות. חוסר תיעוד אינו 0% ואינו 50%, והתוצאה אינה המלצת הצבעה.
- לבחור במפורש עד ארבע רשימות לקריאה זו לצד זו. גם כאן הסדר אלפביתי, ללא ציונים או עדיפות.
- לפתוח פרופילים, תיעוד, מקורות, תאריכים, הסתייגויות והערות גישה. רשומות מסומנות כהצהרה מיוחסת, תיעוד היסטורי, מידע מסויג או פער — לא כ״אמת מאומתת״.

אחוז המצפן הוא חפיפה מתועדת בלבד: נקודות = 4 פחות המרחק בין הכיוון שסומן לקוד העריכתי של רשומה קיימת. אין המלצת הצבעה, אין השלמת פערים, ואין יצוא או שמירת תשובות.

## הפעלה מקומית ופרטיות

פתחו את `index.html` לצד `styles.css`, `app.js`, `data.js`, `issue-data.js` ותיקיית `assets`. הסקריפטים קלאסיים ונדחים, ולכן אפשר להשתמש גם ב־`file://`, ללא שרת, התקנה או חיבור רשת לאחר הורדת הקבצים.

בחירות הקריאה, החיפוש, רשימות ההשוואה ותשובות המצפן נמצאים בזיכרון העמוד בלבד. רענון או ״איפוס התצוגה״ מוחקים אותם. הקוד אינו שומר או שולח אותם ואינו משתמש בעוגיות, `localStorage`, `sessionStorage`, בסיס נתונים בדפדפן, service worker, קידוד תשובות בכתובת, אנליטיקה, שרת יישום או משאבים מרוחקים כגון גופנים ותמונות.

הטענה הזאת מתייחסת לקוד האתר, **לא למארח**: GitHub Pages ורשת ההפצה עשויים להחזיק יומני גישה ומטמונים שאינם בשליטת הלקוח. פתיחת מקור חיצוני היא ביקור באתר אחר ובמדיניותו. קישורים כאלה מוגבלים לכתובות HTTP/HTTPS ציבוריות ונפתחים עם `noopener`, `noreferrer` ו־`no-referrer`.

## המחקר והגבולות שלו

`data\research.json` הוא מקור פרופילי הרשימות, התיעוד והמקורות. `data.js` חושף את אותו אובייקט כ־`window.ELECTION_DATA`, ללא תיקוני מפלגות או עובדות בקוד הממשק.

הממשק תומך ב־`research.roster`: תאריך המיפוי, שלמותו (`complete`, `partial`, `unverified`), בסיס המחקר, מקורות סמכות ומניין, רשומות ומעמדן, והחרגות. מספר הכרטיסים **אינו הוכחה** למיפוי מלא או לאישור רשמי. גם מיפוי מלא המבוסס על דיווחים אינו מתואר כרשימה רשמית שאומתה ישירות. רשומות שנדחו או פרשו אינן מוצגות כרשימות מתמודדות; הסיבות והמקורות נגישים בחלון היקף המחקר.

אותיות קלפי מוצגות רק כשנמסרו עם אסמכתאות במפת הרשימות או ב־`party.ballotSourceIds`. אין טבלת אותיות, שמות מנהיגים או רשימות קבועה בקוד. כשאין אסמכתה זמינה, מופיעה ראשית השם המסומנת **״שם, לא פתק״**.

`data\issue-guide.json` ו־`issue-data.js` מכילים מפת קריאה ניטרלית:

```text
window.ISSUE_GUIDE = {
  version: 1,
  asOfDate,
  questions: [{
    id, topicId, titleHe, promptHe, explanationHe,
    evidenceByParty: { partyId: [evidenceId, ...] }
  }]
}
```

כל הפניה נפתרת למזהה תיעוד מדויק השייך לרשומה ולנושא המתאימים. אין חיפוש מילות מפתח, השלמה מעמדה כללית בנושא או שימוש בקובץ השאלון הפוליטי הישן. מערך הפניות ריק הוא פער במחקר, **לא עמדה בעד, נגד או ניטרלית**. סוג התיעוד יכול לשנות את המקטעים הפתוחים, אך כל הרשימות נשארות מוצגות, וכל התיעוד המקושר עדיין נגיש.

קובץ מחקר חסר או לא תקין מוביל למצב חוסר מידע מפורש, ללא נתוני דוגמה. מפת שאלות חסרה או פגומה אינה מוחלפת במפה מומצאת; פרופילי מחקר תקינים נשארים זמינים בנפרד.

מועד הפרסום, תאריך הייחוס, חותמת האחזור והערות הגישה נשמרים כפי שנמסרו במחקר. תאריך פרסום לא ידוע מוצג ככזה. `retrievedAt` עשוי להיות חותמת משותפת לביקורת, ולא זמן של בקשת HTTP מסוימת; יש לקרוא את הערות המקור. טעינת עמוד או הצלחת בדיקות אינן אימות של נכונות תוכנו. סיכומי המחקר אינם ציטוטים מילוליים; פרסום מפלגתי מתעד הצהרה ולא ביצוע.

## עיצוב ונגישות

עיצוב מקומי ללא תלות: פלטת לילה ושנהב, צבעי הדגשה בניווט ובנושאים בלבד, ומראה אחיד לכל הרשימות. האיורים ב־`assets\*.svg` נוצרו במיוחד לפרויקט; אינם לוגואים מפלגתיים, דיוקנאות או פתקי הצבעה רשמיים.

הממשק משתמש בפקדים סמנטיים, קישור דילוג, כותרות, הודעות מצב, גילוי הדרגתי וחלונות `dialog` עם Escape והחזרת מיקוד. תצוגת ההשוואה נערמת במסכים צרים. אנימציות קצרות בלבד, ומבוטלות עם `prefers-reduced-motion`. בדיקת דפדפן אינה תחליף לבדיקת דיבור קורא מסך ולכל שילובי טכנולוגיות העזר.

## בדיקות

אין צורך בהתקנת חבילות:

```powershell
node --check .\app.js
node --check .\data.js
node --check .\issue-data.js
node --test .\tests\fact-check.test.cjs .\tests\site.test.cjs
```

`validateResearch(data)` נשאר יצוא Node ומחזיר `{ valid, problems, evidenceIndex }`; המסריאלייזר משתמש בו. `validateIssueGuide` בודק את מתכונת השאלות ואת הבעלות והפתרון של ההפניות. הסריאליזציה צריכה לשמר את אובייקטי המחקר בדיוק.

הבדיקות מאמתות מבנה, מטא־נתונים, מקוריות ההפניות למקטע, סדר קבוע, פערים, היעדר מנגנוני התאמה, מצבי איפוס וחוזה פרטיות. הן אינן מאשרות אוטומטית את העובדות או את שלמות רשימת המתמודדים; אלה דורשות ביקורת מקורות נפרדת. לפני פרסום נדרשת גם בדיקת הדפדפן על הקבצים הסופיים, ולאחר הפרסום בדיקת האתר החי.
